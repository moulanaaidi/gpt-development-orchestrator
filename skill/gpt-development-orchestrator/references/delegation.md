# Delegation

Delegate one implementation outcome, not a sequence of tiny coding steps.

A useful Luna handoff contains only:

- goal;
- authoritative spec/repository paths and relevant anchors;
- exact contracts or assumptions that cannot be safely inferred;
- bounded write scope;
- acceptance criteria;
- focused validation commands.

Target at most 500 words, excluding paths and commands. Do not paste large plans, architecture documents, policy text, or routine repository context when the worker can read the authoritative source.

Luna owns scoped discovery, implementation, focused tests, debugging, and routine verification. Do not poll for progress or duplicate its investigation.

Use one writer by default. Parallelize only genuinely independent work with disjoint write sets and verified separate workspaces.

If a material product/architecture/security/shared-contract conflict appears, return one batched blocker report. Ordinary implementation choices stay with the worker.
